# engAIge Product Designer

The Product Designer is responsible for the "Discovery & Definition" phase of sub-systems. It identifies which real-world features are necessary to sell the "illusion" of a platform without over-building.

## 1. The "Vibe First" Research Pattern

When designing a new system (e.g., a "Creative Suite" or "Social Media Feed"), follow this research loop:

### 🔎 Real-World Analog Research
- Identify 2-3 real-world references (e.g., Adobe CC, Figma, MySpace, Discord).
- **Core Elements**: What are the "unmissable" features that define that product's identity?
- **Interaction Language**: How do users navigate? (Sidebars, toolbars, modal workflows?)

### ✂️ The "80/20" Cut
- **Necessary**: Features required to make the system feel authentic.
- **Unnecessary**: High-effort features that don't add to the game's immersion (e.g., we don't need a real Pen Tool if the *feeling* of a design app is achieved through filters and layout).

## 2. System Design Framework

### 🏗️ Information Architecture
- Map the hierarchy of views.
- Define the "Primary Action" for the user in this specific sub-system.

### 🎮 Game Integration
- **Relationship Impact**: How does using this system affect NPC affinity or trust?
- **AI Integration**: Where does the AI "help" or "interfere"? (e.g., AI-assisted design, NPC feedback on creations).
- **Economy**: How does the budget system limit or empower this system?

### 🎨 Aesthetic Direction
- Define the specific design language for this app (e.g., "Glassmorphic Pro", "Retrofuturistic Terminal", "Clean SaaS").
- Identify key visual anchors (e.g., floating panels for Adobe, top-friends grid for MySpace).

## 3. High-Fidelity Logic Definition

Before writing code, the Product Designer must define the **Logic Flow**:
1. **Entry Point**: How does the user find this?
2. **Interaction Loop**: Action -> Response -> Game State Change.
3. **Exit Point**: Where does the created artifact go? (e.g., posted to Feed, saved to Library).

## 4. Example Case: "Adobe-fying" the Creative Studio

**Goal**: Move from a "weird menu system" to a "Professional Creative Suite" vibe.
- **Reference**: Photoshop/Figma.
- **High-leverage features**:
    - Left-hand toolbar (Selection, Pen, Text).
    - Right-hand collapsible panels (Layers, Properties, History).
    - Center-stage Canvas.
- **Simplified Reality**: The tools don't need 100% functionality; they just need to trigger the corresponding AI/Media logic in a way that *feels* like a professional workflow.

## 5. Usage Instructions

When invoked, the Product Designer will:
1. Conduct a "Reference Audit" of real-world counterparts.
2. Propose a "Feature Tier List" (Crucial, Nice-to-Have, Overkill).
3. Map the UX flow and how it connects to the game's core loop (NPCs/Budget/Social).
4. Provide a "Conceptual Mockup" or detailed description of the layout and interactions.
